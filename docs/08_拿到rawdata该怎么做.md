## 第一部分：全景图——从 rawdata 到报告只要走 6 步

```
   ①搞清格式    ②数据体检    ③画图确认    ④写Dataset    ⑤小数据试跑    ⑥全量+评估
   ─────────    ─────────    ─────────    ──────────    ──────────    ─────────
   10 分钟       5 分钟       30 分钟       1 小时        1 小时        看数据量
   一句话说清    发现数据病    用眼睛确认    能取出一个     流程通了      出指标
   一个样本      要不要治      你的预期      样本张量       再上全量      出图出报告
   ```

| 步骤 | 最容易犯的错 | 后果 |
|------|------------|------|
| ① 搞清格式 | 不搞清楚就动手写 | 后面全错 |
| ② 数据体检 | **跳过** | 模型不收敛，却去调参 |
| ③ 画图确认 | **跳过**（觉得浪费时间） | 统计量骗了你也不知道 |
| ④ 写 Dataset | 不写单元测试 | 训练半天才发现标签配错 |
| ⑤ 小数据试跑 | 直接上全量 | 一个 bug 等半小时才暴露 |
| ⑥ 全量+评估 | 只看 accuracy | 类别不均衡时被数字骗 |

**新手 80% 的时间浪费在"跳过 ②③⑤，然后在 ⑥ 反复调参"。**

## 第二部分：rawdata 和"公开数据集"的 5 个关键区别

这是教科书不会讲、但**你拿到导师数据时一定会遇到**的。本项目的 `das_data`
是**论文级公开数据集**——已经清洗过、格式化过、划好 train/test 了。
**导师给你的 rawdata 大概率不是这样。**

### 区别 1：公开数据集是"成品"，rawdata 是"原料"

| | 公开数据集（本项目） | 导师的 rawdata（大概率） |
|---|-------------------|----------------------|
| 格式 | 统一 `.mat`，都是 `data` 变量，(10000,12) | **可能混杂**：不同设备、不同日期、格式不一 |
| 切分 | 已经切成 10000×12 的样本 | **可能是一整段长信号**（几小时的连续记录） |
| 标签 | 已有 `label.txt` | **可能没有**，或只有原始记录表 |
| train/test | 已按 8:2 划好 | **通常没有**，要你自己划 |
| 脏数据 | 基本没有 | **必然有**：缺失、异常、重复、时长不一 |

**所以对 rawdata，第 ② 步（体检）和第 ③ 步（画图）花的时间要翻几倍。**

### 区别 2：最重要的一步是"切样本"，而公开数据集替你做了

本项目的样本是怎么来的？论文第 3 节写了：

> "由于每类事件采集时长和位置不同，后续分类需要统一格式。因此数据被裁剪。
> 裁剪后的时空信号样本由时域 10000 点和空域 12 个相邻点组成。"

**翻译成人话**：原始采集是一长段连续记录，作者**手工切成了固定长度的片段**，
每段 10000 个时间点、12 个空间点。

**你拿到 rawdata 后，这个"切"的动作要你自己做**，而且要回答：

| 问题 | 为什么重要 | 本项目的答案 |
|------|-----------|-------------|
| 切多长？ | 太短装不下一个完整事件，太长混入多个事件 | 10000 点（5km 光纤对应 0.8 s，10km 对应 1.25 s） |
| 空间取几个点？ | 决定模型能不能看到事件的空间范围 | 12 个相邻点（10 m/点） |
| 从哪个位置开始切？ | 扰动发生的位置不同 | 论文："只选取扰动位置附近的点（多数在中心）" |
| 要不要重叠切？ | 不重叠样本少，重叠又会让 train/test 泄漏 | 论文未说明（**这是一个可以问导师的点**） |
| 边界怎么处理？ | 事件可能跨两个片段 | — |

**这一步做错了，后面所有实验都白做。** 而它**没有标准答案**，取决于物理场景。

### 区别 3：标签可能是最脏的一环

公开数据集的 `label.txt` 是作者整理好的。**rawdata 的标签往往是一张 Excel 表**，
长这样：

```
日期        时间      文件编号   事件类型   操作人   备注
20220104   14:23:11   sys_01    挖掘       系统     沙箱，15cm深
20220104   14:31:02   sys_02    挖掘       系统
20220104   15:02:44   sys_03    ???        系统     不确定是什么
```

**你要做的**：
1. **对齐**：文件名 → 标签，格式转换
2. **查冲突**：同一个文件在表里出现两次且标签不同？
3. **查缺口**：有文件没标签？有标签没文件？
4. **处理"不确定"**：上表第三行那种怎么办？——**扔掉，还是让导师确认？**

> ⚠️ **这一步必须先问导师**，不要自己猜。
> "不确定"的样本留着会污染训练，扔掉又可能扔掉关键类别。

**本项目遇到的同类问题**：官方仓库 issue #12/#13 反映 `label.txt` 的行顺序
和文件名顺序不一致，而代码按行读 → 会导致**标签整体错配**。
我专门写了校验（对每一类比对磁盘顺序与 label 顺序）确认本数据集没问题。

**你以后拿到 rawdata，这个校验一定要做**：

```python
# 校验：label.txt 的顺序和磁盘文件顺序是否一致
disk_order = sorted(os.listdir(class_dir))
label_order = [从 label.txt 提取的本类文件，保持原顺序]
print('一致' if disk_order == label_order else '不一致，有错配风险！')
```

### 区别 4：空域维度可能根本不存在

本项目每个样本是 `(10000, 12)`——**10000 个时间点 × 12 个空间点**。
这个"12"来自 Φ-OTDR 系统的物理特性：光脉冲沿光纤传播，
采集卡同时记录沿线多个位置的背向散射光。

**但你导师的数据可能是**：
- 单个传感器的时序数据 → 形状 `(N,)`，**没有空间维**
- 多个传感器但不同步 → 需要先做时间对齐
- 摄像/图像数据 → 形状 `(H, W, C)`

**形状不同，模型就完全不同**：
- `(10000, 12)` 二维 → 用 **2D 卷积** `Conv2d`
- `(10000,)` 一维 → 用 **1D 卷积** `Conv1d` 或 RNN
- `(H, W, C)` → 用 2D 卷积，但要调整通道顺序

**所以第 ① 步"一句话说清一个样本是什么"极其关键**——它决定了后面全部选型。

### 区别 5：领域预处理是"隐形需求"

论文为什么要做**差分**？因为原始信号有个很大的直流底（背景光强），
事件引起的波动被淹没了。差分相当于高通滤波。

**这个操作不是"通用最佳实践"，是 Φ-OTDR 这个领域的知识。**

**你换一个领域，预处理就完全不同**：

| 领域 | 典型预处理 |
|------|-----------|
| 振动/声波信号 | 差分、去趋势、带通滤波、STFT 转时频图 |
| 心电/脑电 | 工频陷波（50Hz）、基线漂移校正、伪迹剔除 |
| 图像 | 去噪、几何校正、颜色归一化 |
| 文本 | 分词、去停用词（现在多用子词） |
| 表格/传感器 | 缺失值填充、异常值处理、类别编码 |

**所以拿到 rawdata 后，一定要问导师**：

> "这个数据采集的物理原理是什么？信号里哪些成分是干扰、哪些是信号？
> 有没有这个领域常规的预处理步骤？"

**这个问题问出来，导师会知道你是在认真做研究，而不是在盲目套模型。**

## 第三部分：行动清单（可直接照着做）

### 阶段 A：先问清楚（动手之前，半天）

**给导师的问题清单**（建议一次问完）：

```
1. 任务目标
   - 要做什么？分类 / 回归 / 检测 / 分割？
   - 输入是什么、输出是什么？
   - 有多少个类别？类别定义是什么？

2. 数据来源
   - 采集设备和物理原理是什么？
   - 采集环境、时间跨度、操作人员？
   - 有没有已知的问题（某些时段数据质量差等）？

3. 标签
   - 标签在哪？谁标的？怎么标的？
   - 有没有"不确定"或存在争议的样本？
   - 标签的可信度如何（如果人工标注，标注一致性怎么保证）？

4. 评价标准
   - 达到什么水平算成功？
   - 有没有基线可以对比（已发表结果 / 之前师兄师姐的结果）？

5. 领域知识
   - 信号里哪些是干扰、哪些是目标？
   - 有没有常规的预处理步骤？
   - 有没有推荐的参考文献？

6. 边界
   - 时间节点？算力限制？需不需要发论文？
```

> **这一步不能省。** 我见过太多人花两周做了个模型，
> 导师说"我不是要分类，我是要检测异常起始时刻"——方向从一开始就错了。

### 阶段 B：数据摸底（1~2 天）

```
① 搞清格式（10 分钟）
   打开一个文件，打印变量名、形状、类型 → 写一句话

② 跑体检（5 分钟）
   改 data_profile.py 的 CONFIG 区域 → python data_profile.py

③ 画图（30 分钟~2 小时）
   每一类至少画 3 个样本，用眼睛看
   ★ 这一步在 rawdata 上要比公开数据集多花几倍时间

④ 标签核对（30 分钟）
   - 标签表和文件名能否一一对齐
   - 有没有缺失、重复、矛盾的标签
   - 每类数量统计，看是否严重不均衡
   - train/test 有没有重叠（如果自己划）
```

**产出**：一份**数据体检报告**（可以就是 `data_profile.py` 的输出 + 你画的图）。
**这份东西很重要**——它是你和导师讨论的共同基础。

### 阶段 C：数据工程（2~5 天，最耗时）

```
① 写"切样本"脚本
   - 从长信号切出固定长度片段
   - 决定：切多长、从哪切、要不要重叠
   - ★ 这一步的决定要记录，将来写论文要写清楚

② 写标签对齐脚本
   - 生成统一格式的 label.txt（路径 + 标签）
   - 做顺序校验（见上文）

③ 划分 train / val / test
   - 怎么划？（随机？按时间段？按人？按设备？）
   - ★ 这是数据泄漏的高危区！
   - ★ 如果是时序数据，绝对不能随机划（会泄漏）

④ 写 Dataset
   - 照抄三层结构，改 __getitem__
   - 必做单元测试（6 行代码，见 06 号文档第 4 步）
```

**关于划分方式，这是最容易出科研事故的地方**：

| 场景 | 错误划法 | 正确划法 |
|------|---------|---------|
| 普通分类 | — | 随机 8:2 |
| **同一段信号切出的片段** | 随机划分 ❌ | **按整段划分**（同一段的片段不能跨 train/test） |
| 时序预测 | 随机划分 ❌ | **按时间前后划分** |
| 多人采集的数据 | 随机划分（可能偏乐观） | 留一交叉验证（按人划分） |

> **本项目的划分是安全的**——论文说"训练和测试数据按 8:2 随机选取，
> 两者无重叠"，而且是**作者已经从原始数据里切好的独立样本**，
> 不存在"同一段信号被切开分到两边"的问题。
> 我在体检时也验证了 train/test 无重叠。

### 阶段 D：建模与实验（方法同上，但顺序不能颠倒）

```
① 先用极小数据跑通流程
   - 40 个样本、2 个 epoch，只看 loss 能不能降
   - 确认：数据能读、模型能前向、loss 能反向、参数能更新
   - ★ 这一步能省掉几天的 Debug 时间

② 建立基线
   - 先跑最简单的模型（SVM / 逻辑回归 / 3 层 CNN）
   - 目的：拿到一个"及格线"，后面的改进才有参照

③ 优化数据加载性能（如果需要）
   - 先测：一个 epoch 花多久？瓶颈在数据还是模型？
   - 只优化瓶颈（本项目：瓶颈在 Python 循环，不在 GPU）

④ 调参 / 改模型
   - 每次只改一个变量
   - 记录每次的结果（参数 + 指标）

⑤ 多种子重复实验
   - 给出"均值 ± 标准差"
   - ★ 单次结果在论文里是站不住的
```

### 阶段 E：交付（1~2 天）

```
① 出图（混淆矩阵、曲线、对比图）
② 出表（逐类 P/R/F1，与基线对比）
③ 写报告
   - 结论先行
   - 附上数据体检结果、bug 记录、局限说明
④ 整理代码与产出物
   - 原始版本和修改版本并存
   - results/ 里所有图带参数命名（否则一周后分不清哪张是哪次）
```

## 第四部分：整个项目里，什么是"通用"的、什么是"每次都要重做"的

**这张表最有价值**——它告诉你哪些技能可以带走，哪些每次都得重新学。

### ✅ 完全通用（一次学会，处处能用）

| 技能 | 对应本项目文件 |
|------|--------------|
| 虚拟环境、包管理 | `01_环境配置_CUDA.md` |
| 环境自检 | `env_check.py` |
| 数据体检的思路与工具 | `data_profile.py` |
| PyTorch `Dataset` / `DataLoader` 三层结构 | `mydataset.py` |
| 训练脚本骨架（train/test/main） | `das_data_cnn.py` |
| `model.train()` / `model.eval()` / `no_grad` 的区别 | 同上 |
| 混淆矩阵与 P/R/F1 计算 | `das_data_svm.py` |
| 多种子重复实验 | `run_cnn_seeds.py` |
| 向量化优化（NumPy 替代 for 循环） | `reference_feature_extraction.py` |
| 等价性验证（优化前后逐位对比） | 验证脚本 |
| GPU/CPU 设备管理 | `das_data_cnn.py` 第 47 行修复 |
| 随机种子固定 | `run_cnn_seeds.py` |

### ⚠️ 每次都要重新做（依赖具体项目）

| 事项 | 为什么每次不同 | 本项目的情况 |
|------|--------------|-------------|
| **一个样本是什么** | 由传感器和采集方式决定 | 10000 时间点 × 12 空间点 |
| **怎么切样本** | 由事件持续时长决定 | 10000 点（0.8~1.25 s） |
| **领域预处理** | 由物理原理决定 | 差分（去除直流底、凸显快变事件） |
| **网络结构选择** | 由数据形状决定 | 数据是 2D → 用 2D 卷积 |
| **性能指标** | 由任务决定 | 6 类分类 → 准确率/F1/NAR |
| **数据划分方式** | 由数据来源决定 | 作者已划好，无需处理 |
| **特征工程** | 由信号特点决定 | 16 个时域统计量 |

**带走左边，右边每次问导师。**

## 第五部分：如果现在给你一份 rawdata，你的第一小时

```
第 0~10 分钟
  □ 找到数据，列出所有文件
  □ 打开一个文件，打印变量名/形状/类型
  □ 写一句话："一个样本是 ______"

第 10~25 分钟
  □ 数一数：有几个类别？每类多少文件？
  □ 看一眼标签文件长什么样（Excel? txt? 文件名里带？）
  □ 确认：有没有 train/test 划分

第 25~45 分钟
  □ 画 3 个样本的图（每类一个）
  □ 看数值范围、有没有异常
  □ 问自己："图和我预期的一样吗？"

第 45~60 分钟
  □ 列出你不确定的问题（准备问导师）
  □ 改 data_profile.py 的 CONFIG，跑一次体检
  □ 根据体检结果写一份 5 行的"数据现状小结"
```

**第一小时的产出不是代码，是"我搞清楚了数据长什么样，以及我还有哪些不懂"。**

## 第六部分：给导师汇报 rawdata 进展的模板

```
X 老师您好，汇报 [项目名] 的初步进展：

【数据摸底】
- 数据规模：共 ___ 个文件，___ 个类别
- 单样本格式：___（形状 ___，类型 ___）
- 标签情况：___（在哪个文件、格式、有无缺失/冲突）
- 数据划分：___（已有 / 需要我自己划）

【体检发现】
- 数据质量：___（缺失值、异常、重复的情况）
- 类别分布：___（是否均衡）
- 需要处理的问题：___

【初步观察】
（附上画的图）从图上看到 ___ 类的形态是 ___，与预期 ___（一致/不一致）

【需要您确认的问题】
1. ___（比如：某些样本标签不确定，是保留还是剔除？）
2. ___（比如：数据划分方式有没有要求？）
3. ___（比如：这个信号里 ___ 属于干扰还是目标？）

【下一步计划】
- 完成样本切分与标签对齐
- 建立基线模型（预计用 ___ 方法）
- 预计 ___ 天出第一版结果
```

**注意"需要您确认的问题"这一栏——这是最重要的一栏。**
它同时做到三件事：
1. 让导师知道你真的看懂数据了
2. 把决策责任交回给应该负责的人（领域知识在你导师那里）
3. 避免你自己猜错了方向，白干两周
