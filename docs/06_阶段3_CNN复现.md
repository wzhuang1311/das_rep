## 一、你要理解的核心问题：GPU 被 CPU 饿死了

这是本阶段最重要的一件事。先看**实测数据**（你机器上跑出来的，不是估算）：

| 环节 | 耗时 | 在哪算 |
|------|------|--------|
| 一个 batch（100 样本）**前向+反向** | **0.482 秒** | GPU |
| 一个 batch（100 样本）**数据加载+归一化** | **15.24 秒** | CPU |

**CPU 是 GPU 的 32 倍慢。**

### 这意味着什么

```
一次训练迭代的时间线（官方代码）：

GPU:  ├─0.48s─┤                                    ├─0.48s─┤
                 （GPU 空转 15.24 秒，什么也不干）
CPU:  ├────────── 15.24 秒 准备数据 ──────────────┤

总时间 = 15.24 + 0.48 ≈ 15.7 秒/批
GPU 利用率 = 0.48 / 15.7 ≈ 3%
```

**GPU 有 97% 的时间在空转。** 你花大价钱买的显卡，大部分时间在等 CPU 喂数据。

### 换成年份级的账

| | 数据加载 | GPU 计算 | 实际总时间 |
|---|---------|---------|-----------|
| 官方代码 | **26.1 小时** | 49.8 分钟 | **约 27 小时** |
| 优化后 | 23 分钟 | 49.8 分钟 | **约 1.2 小时** |

**注意：GPU 计算时间两边完全一样（49.8 分钟）。** 优化只动了 CPU 那边。
这就是"**找瓶颈**"的价值——**优化错了对象，再努力也没用**。

## 二、瓶颈在哪一行代码

`mydataset.py` 第 6-12 行：

```python
def normalize(data):                           # 归一化到0-255
    rawdata_max = max(map(max, data))
    rawdata_min = min(map(min, data))
    for i in range(data.shape[0]):             # 10000 次
        for j in range(data.shape[1]):         # × 12 次
            data[i][j] = round(((255 - 0) * (data[i][j] - rawdata_min)
                                / (rawdata_max - rawdata_min)) + 0)
    return data
```

**这段代码要执行 10000 × 12 = 12 万次 Python 层循环。**

而且注意：**归一化是逐个元素做的**——每次只处理一个数字。这正是"Python 循环慢"的典型场景。

实测：

| 版本 | 每样本 | 相对速度 |
|------|--------|---------|
| 官方双层 for | 0.1524 秒 | 1× |
| 向量化 | 0.0022 秒 | **68 倍快** |

## 三、为什么 PyTorch 没能自动帮你并行

官方代码第 135、137 行：

```python
train_loader = DataLoader(dataset=train_dataset, batch_size=args.batch_size, shuffle=True)
```

`DataLoader` 有一个参数叫 `num_workers`，**默认值是 0**，意思是：

> **"用主进程顺序加载数据，不要开子进程。"**

官方代码没写这个参数，所以就是 0 —— 单线程，一个接一个地归一化，
**GPU 只能干等**。

**而你的 CPU 有 24 个逻辑核心，全闲着。**

## 四、两个优化手段（可以叠加）

| 手段 | 原理 | 预期效果 |
|------|------|---------|
| **① 向量化** | 让"12 万次单个运算"变成"一次数组运算" | 68 倍 |
| **② `num_workers=4`** | 开 4 个子进程同时准备数据 | 最多再 4 倍（但此时已不是瓶颈） |

**先做①**，因为：
- 它是根本问题（代码写法）
- ②只是"多开几个人干同一件蠢事"，①是"把蠢事变成聪明事"
- 做完①之后，数据加载只要 0.2 秒/批，**已经比 GPU 快了，不需要再并行**

> **工程原则**：先优化算法/写法，再考虑加资源。**反过来做通常是浪费。**

## 五、CNN 训练脚本的结构（你以后写任何训练脚本都是这个骨架）

`das_data_cnn.py` 的组织方式，值得你记住：

```python
def train(model, train_x, train_y, optimizer, criterion):
    """一个 batch 的训练：前向 -> 算损失 -> 反向 -> 更新参数"""
    model.train()
    model.zero_grad()
    _, probs = model(train_x)                      # 前向传播
    loss = criterion(probs, train_y)               # 算损失
    loss.backward()                                # 反向传播（你鱼书学过的那部分）
    optimizer.step()                               # 更新参数
    return labels, predi, loss.item()

def test(model, dataset, criterion):
    """在测试集上评估：不更新参数，只统计准确率和混淆矩阵"""
    model.eval()                                   # 切换 eval 模式
    for ... :
        feature, probs = model(batch_x)
        _, pred = torch.max(probs, dim=1)           # 取分数最高的类
    accuracy = accuracy_score(labels, prediction)
    C = confusion_matrix(labels, prediction)
    return accuracy, val_loss, feature_list, C

def main(args):
    # ① 数据
    train_loader = DataLoader(...)
    # ② 模型
    model = CNN()
    if torch.cuda.is_available(): model = model.cuda()
    # ③ 优化器和损失
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-4, weight_decay=1e-5)
    criterion = nn.CrossEntropyLoss()
    # ④ 训练循环

        for (cnt, i) in enumerate(train_loader):     # 逐 batch

        # 每个 epoch 结束，在测试集上评估
        acc_score, loss_score, feature_list, C = test(model, test_loader, criterion)
        print("Epoch %d Val_accuracy %.3f Val_loss %.3f" % (epoch, acc_score, loss_score))
    # ⑤ 最后一轮保存模型、画图
```

**对比你学过的鱼书**：鱼书里的 `TwoLayerNet` 手写了 `forward` / `backward` / `numerical_gradient`。
PyTorch 把这些都自动化了：
- `loss.backward()` = 鱼书里的 `backward()`（自动求导，不用手写）
- `optimizer.step()` = 鱼书里的 `params[key] -= lr * grad[key]`
- `nn.Conv2d` / `nn.Linear` = 鱼书里的 `Affine` 层
- `nn.CrossEntropyLoss` = 鱼书里的 `SoftmaxWithLoss`

**你学的误差反向传播，就是 `loss.backward()` 背后发生的事。**

## 六、官方代码里的几个"怪但无害"的地方（知道就行）

# 改前（12 万次 Python 循环）
def normalize(data):
    rawdata_max = max(map(max, data))
    rawdata_min = min(map(min, data))
    for i in range(data.shape[0]):
        for j in range(data.shape[1]):

# 改后（一次数组运算）
def normalize(data):
    mn, mx = data.min(), data.max()
    return np.round(255.0 * (data - mn) / (mx - mn))

## 九、术语速查

| 术语 | 解释 |
|------|------|
| **epoch** | 把训练集完整过一遍 |
| **batch** | 一次喂给模型的一小批样本（这里是 100 个） |
| **iteration** | 处理一个 batch，叫一次迭代。1 epoch = 124 iterations |
| **DataLoader** | PyTorch 的数据搬运工，负责按 batch 取数据 |
| **num_workers** | DataLoader 开几个子进程准备数据。默认 0 = 不开 |
| **GPU 利用率** | GPU 实际在计算的时间占比。本例官方代码只有约 3% |
| **饿死（starving）** | GPU 等不到数据而空转，是深度学习最常见的性能问题 |
