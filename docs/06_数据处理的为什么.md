## 一、核心心智模型：数据处理是一条流水线

**所有**深度学习项目都是这五步。记住这张图，你以后面对任何任务都不会懵：

```
①原始数据  →  ②清洗/体检  →  ③加载(Dataset)  →  ④模型  →  ⑤评估
   .mat          data_profile      PyTorch         CNN      混淆矩阵
   .csv          看出来有啥问题      DataLoader     SVM      precision
   .jpg          决定怎么处理        batch/打乱                F1
```

| 阶段 | 你要回答的问题 | 产出 |
|------|--------------|------|
| ① 原始数据 | 数据在哪？什么格式？ | 找到文件 |
| ② 清洗/体检 | 数据干净吗？有问题吗？ | **一份"数据体检报告"** |
| ③ 加载 | 怎么喂给模型？ | `Dataset` + `DataLoader` |
| ④ 模型 | 用什么结构？ | 网络定义 + 训练循环 |
| ⑤ 评估 | 效果如何？可信吗？ | 指标 + 混淆矩阵 |

**新手最大的错误**：直接跳到第 ④ 步（抄个网络就开跑），
结果模型不收敛，然后花三天调参——**其实问题出在第 ②③ 步**。

> 我这几天带你做的事，其实就是按这个顺序走的：
> 阶段 1 = 第 ② 步，阶段 2/3 = 第 ③④ 步。**顺序本身就是教学内容。**

## 二、"数据清洗"到底是什么意思？

先纠正一个误解：**数据清洗 ≠ 一定要改数据**。

清洗的本质是**三个动作**：

```
第一步：检测（有没有问题？）    ← 最重要，占 80% 的功夫
第二步：判断（这个问题影响大吗？）  ← 需要领域知识，不是纯技术
第三步：决策（改？扔？留？标记？）  ← 改之前先想清楚代价
```

**新手最容易犯的错是跳过第一步直接改**。比如看到几个异常值就全删掉，
结果删掉了真正的信号——**在信号识别任务里，异常往往就是你要找的东西！**

### 常见的"数据病"和处方

| 病症 | 怎么检测 | 处方 | 什么情况下**不要**用这个处方 |
|------|---------|------|---------------------------|
| **缺失值**（NaN/空） | `np.isnan(x).sum()` | 删掉该样本 / 用均值填充 / 用前后值插值 | 缺失本身有含义时（比如"传感器没响应"就是一种状态） |
| **异常值** | 看数值范围、画箱线图 | 3σ 原则截断 / 分位数截断 | **信号识别任务里，异常可能就是信号！**（本文的敲击事件就是尖峰） |
| **重复样本** | 文件哈希比对、特征比对 | 去重 | 如果是有意增广的数据 |
| **类别不平衡** | 统计每类数量 | 重采样 / 类别权重 / 换评估指标 | 不平衡程度 < 2 倍时，通常不用管 |
| **数据泄漏** | **检查 train/test 有没有重叠** | 删掉重叠 | 永远不要放过这个！ |
| **坏样本**（全 0、常量） | `std == 0` | 删掉 | — |
| **量纲不一** | 看各特征数值范围 | 标准化/归一化 | 树模型（随机森林）不需要 |

### 对本数据集：我们应该做什么清洗？

我用 `data_profile.py` 体检过了，结论是：

| 检查项 | 结果 | 需要处理吗 |
|--------|------|-----------|
| 文件完整性 | train 12335 + test 3084，与 label.txt 完全一致 | ❌ 不用 |
| 变量名/形状/类型 | 全部是 `data`, (10000,12), uint16 | ❌ 不用 |
| NaN | 没有 | ❌ 不用 |
| 类别平衡 | 最多/最少 = 1.31 倍 | ❌ 不用（轻度） |
| train/test 重叠 | 无重叠 | ❌ 不用 |
| 死通道 | 无 | ❌ 不用 |
| 坏样本 | 没发现 | ❌ 不用 |

**所以答案是：这个数据集不需要"清洗"，只需要"归一化"。**

这本身就是重要认识：**高质量公开数据集（论文级）通常是干净的**。
清洗的功夫主要花在**自己采的数据**上——而那一天迟早会来。

### ⚠️ 一个反直觉的发现（请重点看）

我在体检时发现：

| 类别 | 样本全局标准差 |
|------|--------------|
| 背景噪声 | **392.1** ← 最大 |
| 挖掘 | 106.9 ← 比背景还小 |
| 敲击 | 245.6 |

**"标准差大 = 有事件"这个直觉是错的。**

为什么？看通道级的 std：

```
挖掘:  [16.6 16.3 20.1 37.0 59.9 64.9 59.1 63.9 36.0 22.9 17.6 15.9]
        ↑──── 安静背景 ────↑ ↑──────── 扰动区 ────────↑ ↑── 安静 ──↑

背景:  [45.1 42.5 78.8 70.7 23.0 19.1 17.1 18.4 28.3 37.6 32.9 22.0]
        ↑── 各种环境干扰散布在多个通道 ──↑
```

**背景噪声是"到处都乱但都不太剧烈"，挖掘是"局部非常剧烈、其余安静"。**

**这个发现的教学意义**：
1. **不能用几个全局统计量区分事件**——这解释了为什么论文的 SVM（用全局统计特征）只有 82.6%，
   而 CNN（看完整的时空模式）能做到 94%。**这个因果链，就是你复现报告里最有价值的一段分析。**
2. **医学/工程领域的通病**：先画图，再看统计量，不要反过来。

## 三、数据怎么"导入"？—— PyTorch 数据加载的三层结构

这是你以后每个项目都要写的东西。**搞懂这三层，PyTorch 数据加载就再也不是黑箱了。**

```
┌─────────────────────────────────────────────────────────┐
│  第 3 层：DataLoader     负责"怎么批量喂"                 │
│    - batch_size：一次喂几个样本                          │
│    - shuffle：要不要打乱顺序                             │
│    - num_workers：用几个进程并行读（Windows 上写 0！）    │
│    - 产出：一次 yield 一个 batch                         │
└────────────────────────┬────────────────────────────────┘
                         │ 向第 2 层要数据
┌────────────────────────▼────────────────────────────────┐
│  第 2 层：Dataset        负责"怎么取一个样本"             │
│    - __init__：准备阶段，只做一次（读文件列表等）          │
│    - __len__：告诉别人一共有多少个样本                    │
│    - __getitem__(i)：取出第 i 个样本 ← 核心！             │
│      这里是"读文件 → 处理 → 转张量"发生的地方             │
└────────────────────────┬────────────────────────────────┘
                         │ 向第 1 层要数据
┌────────────────────────▼────────────────────────────────┐
│  第 1 层：原始文件         .mat / .csv / .jpg            │
│    - 磁盘上的东西，模型看不懂，必须经过第 2 层转换         │
└─────────────────────────────────────────────────────────┘
```

### 为什么 PyTorch 要设计成三层？三个理由

**理由 1：数据太大，装不进内存。**
你总共 15419 个样本 × 10000×12 × 4 字节 ≈ **7.4 GB**。
如果用"一次性全读进内存"的写法（就像 `get_das_data.py` 那样），
内存吃紧，数据量再大 10 倍就直接崩。

`Dataset` 的设计哲学是**"按需读取"**：`__getitem__(i)` 被调用时才去读第 i 个文件。
DataLoader 每次只要 100 个，内存里就永远只有 100 个样本。

**理由 2：模型训练需要"批量"和"随机"。**
- **批量**：一次算 100 个样本的梯度，比一个一个算稳定得多也快得多
- **随机打乱**：每个 epoch 打乱顺序，防止模型记住"第 1 个样本一定是背景噪声"

这些逻辑如果写在训练循环里，每个项目都要重写一遍。
PyTorch 把它抽出来做成 `DataLoader`，**一次学会，处处能用**。

**理由 3：解耦。**
你的模型不关心数据是 `.mat` 还是 `.csv`，它只要求"给我一个 batch 的张量"。
换数据格式时，**只改 `Dataset`，模型代码一行不动**。

### 对照：官方代码是怎么用这三层的

**CNN 路线（标准做法，值得学）**：

```python
# 第 2 层：定义怎么取一个样本
class MyDataset(Dataset):
    def __init__(self, root_dir, names_file):     # ① 只读文件列表，不读数据
        ...
    def __len__(self):                            # ② 告诉总数
        return self.size
    def __getitem__(self, idx):                   # ③ 真正读数据的地方
        data_path = self.root_dir + self.names_list[idx].split(' ')[0]
        rawdata = scio.loadmat(data_path)['data'] # 打开 .mat
        rawdata = rawdata.astype(int)             # 类型转换
        data = normalize(rawdata)                 # 归一化
        label = int(self.names_list[idx].split(' ')[1])
        return {'data': data, 'label': label}     # 返回一个样本

# 第 3 层：批量
train_loader = DataLoader(dataset=train_dataset, batch_size=100, shuffle=True)
```

**SVM 路线（反例，别学）**：

```python
# get_das_data.py —— 一次性把所有数据读进内存的大数组
temp = np.empty([len(name_list), 12, 32])   # 预分配 12335×12×32
for i in range(len(name_list)):
    rawdata = scio.loadmat(path)['data']    # 一个一个读
    ...                                      # 全部读完才返回
return temp, label_temp
```

**为什么 SVM 要这样写？** 因为 scikit-learn 的 `clf.fit(X, y)` 要求
**X 是一个完整的二维数组**，它不接受"按需取样的 Dataset"。
这是 sklearn 和 PyTorch 设计哲学的根本差异。

**代价**：内存占用大、无法增量处理、无法多进程加速。
**所以**：数据量再大一点，这种写法就崩了。**你自己的项目请用 Dataset 写法。**

### 写 Dataset 时的 5 个实战注意点

```python
class MyDataset(Dataset):
    def __init__(self, ...):
        # ① 只做"轻"的事：读文件列表、检查文件存在
        #    千万不要在这里读全部数据！否则 __init__ 要跑几分钟
        self.names_list = [...]          # 好的做法
        # self.all_data = [load(f) for f in files]   # 坏的做法！

        # ② Windows 上中文路径必须指定编码
        with open(names_file, encoding='utf-8') as f:    # 加 encoding！
            ...

    def __getitem__(self, idx):
        # ③ 每次都重新读文件（不要缓存成全局变量，否则多进程会出问题）
        data = load(paths[idx])

        # ④ 返回类型要想清楚：
        #    - 返回 numpy 数组：DataLoader 会自动转成 tensor（推荐，简单）
        #    - 返回 tensor：省一次转换，但要自己保证类型对
        #    标签建议返回 python int，DataLoader 会自动组装成 int64 张量

        # ⑤ 形状要对：
        #    图像是 (C, H, W)，这里是 (10000, 12)
        #    少了通道维，在训练循环里用 unsqueeze(1) 补上（官方就是这么做的）
        return {'data': data, 'label': label}
```

## 五、案例：三个真实问题的排查思路

### 案例 A：模型 loss 不降，怎么办？

**排查顺序**（从便宜到贵，不要跳）：

```
1. 数据对不对？   → 打印一个 batch，看数值范围、标签分布
2. 能不能过拟合 1 个样本？ → 只拿 1 个样本训练 100 次，
                            如果 loss 降不到 0，肯定是代码有问题
3. 学习率对不对？ → 太大震荡、太小不动。试 1e-1 / 1e-3 / 1e-5
4. 归一化做了吗？ → 输入数值范围是不是在合理区间
5. 最后才怀疑网络结构
```

**第 2 条"能不能过拟合一个样本"是黄金测试**：
如果模型连一个样本都记不住，那问题 100% 在代码或数据，不在超参数。

### 案例 B：准确率看着高，但是假的

**三种常见假象**：

| 假象 | 怎么发现 | 真相 |
|------|---------|------|
| 类别不平衡 | 看每类数量 | 全猜多数类也能有高 accuracy |
| 数据泄漏 | 检查 train/test 重叠 | 测试样本训练时见过了 |
| 预处理泄漏 | 检查 scaler 在哪 fit | 用测试集统计量处理了测试集 |

**本项目的教训**：官方代码 `das_data_svm.py` 第 37 行就是
`minMaxScaler.fit_transform(X_test)` —— 典型的预处理泄漏。
虽然对 MinMaxScaler 影响小，但**这个检查动作你必须养成习惯**。

### 案例 C：跑得太慢

**排查顺序**：

```
1. GPU 用上了吗？        → torch.cuda.is_available(), 看 nvidia-smi
2. 数据加载是瓶颈吗？     → 掐表对比"只加载数据"和"加载+训练"的耗时
3. 有没有 Python 循环套数组运算？ → 最常见！本项目 30 小时 vs 7 分钟
4. 最后才考虑换模型
```

**第 3 条本项目的例子就是最好的教材**：
`mydataset.py` 的双层 for 循环，向量化后快 240 倍。
**见到 `for` 套在数组运算外面就要警觉**，这是深度学习的头号性能杀手。

## 六、把这套方法用在本项目上：完整对照

| 流水线阶段 | 本项目做了什么 | 用的工具 |

**注意第 ③ 步有两条完全不同的路线**——这正好让你对比两种加载范式的优劣：
