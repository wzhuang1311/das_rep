## 二、逐文件讲解

### 1. `mydataset.py`（44 行）—— 数据加载

**它做了什么**：继承 PyTorch 的 `Dataset`，把 `.mat` 文件包装成 PyTorch 能用的数据集。

三个必须掌握的方法（这是 PyTorch 数据加载的标准范式，以后所有项目都一样）：

| 方法 | 作用 | 返回值 |
|------|------|--------|
| `__init__` | 读 `label.txt`，把所有文件路径存成列表 | — |
| `__len__` | 返回**样本总数** | `12335` |
| `__getitem__(idx)` | 读第 idx 个样本，返回一个 dict | `{'data': 张量, 'label': 整数}` |

**关键细节**：`__getitem__` 里 `rawdata = rawdata.astype(int)`。
为什么要转？因为原数据是 `uint16`（无符号），后面做运算会溢出。**转成 int32 是必要的。**

`normalize()` 把每个样本**自己的最大最小值**映射到 0~255（论文 4.2 节说的"模拟灰度图"）。
注意是**每个样本各自归一化**，不是全局归一化——这是论文明确写的。

> ⚠️ **这个文件有个致命性能问题，见第四节。**

### 2. `models.py`（32 行）—— CNN 网络结构

**这是全仓库最短也最重要的文件**，就是你论文 Table 3 的实现。逐层拆开：

```python
输入 x: (batch, 1, 10000, 12)        # 1 是"通道数"，像灰度图只有 1 个通道
   │
   ▼ conv1: Conv2d(1→5, kernel=(200,3), stride=(50,1), padding=1)
      → ReLU
      → MaxPool2d(kernel=2, padding=1)
   │
   ▼ conv2: Conv2d(5→10, kernel=(20,2), stride=(4,1), padding=1)
      → ReLU
      → MaxPool2d(kernel=2)
   │
   ▼ x.view(x.size(0), -1)      # 展平成 (batch, 400)
   │
   ├──→ feature  （400 维特征，返回出来给 LDA 可视化用）
   └──→ self.out: Linear(400 → 6)  → output（6 类的得分 logits）
```

**三个新手必须理解的参数**：

| 参数 | 含义 | 这里的值说明什么 |
|------|------|-----------------|
| `kernel_size=(200, 3)` | 卷积核大小 | **时间方向 200 点、空间方向 3 点**。时间上看得"很长"（200×0.08ms≈16ms 的窗口），空间上只看相邻 3 个点。这是因为事件在时间上有持续特征，在空间上只影响局部 |
| `stride=(50, 1)` | 步长 | 时间方向跳 50 步（降采样 50 倍），空间方向不跳。10000 点经过这层变成约 197 点 |
| `padding=1` | 边缘填充 | 让输出尺寸不至于掉太快 |

**为什么 `forward` 要返回两个值？** `feature` 是给 `feature_visualization.py` 画 LDA 图用的，
`output` 才是分类结果。**你自己写的时候可以只返回 output，不影响复现准确率。**

**这个网络有多小？** 全部参数约 **4300 个**（卷积层 3000 + 全连接 2400）。
对比一下：ResNet-50 有 2500 万个参数。**这说明这个任务的特征其实很"浅"，不需要大模型**——
这本身就是一个值得写进报告的认识。

### 3. `das_data_cnn.py`（218 行）—— CNN 训练主程序

**结构**（这个骨架你以后写任何 PyTorch 训练脚本都是这个套路）：

```python
def main(args):
    # ① 数据
    train_dataset = MyDataset(...)         # 用 mydataset.py
    train_loader  = DataLoader(batch_size=100, shuffle=True)

    # ② 模型
    model = CNN()                          # 用 models.py
    if torch.cuda.is_available(): model = model.cuda()

    # ③ 优化器和损失
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-4, weight_decay=1e-5)
    criterion = nn.CrossEntropyLoss()

    # ④ 训练循环
    for epoch in range(50):
        for (cnt, i) in enumerate(train_loader):     # 逐 batch
            batch_x = i['data']
            batch_y = i['label']
            batch_x = torch.unsqueeze(batch_x, dim=1)  # (100,10000,12) → (100,1,10000,12)
            batch_x = batch_x.float()
            if torch.cuda.is_available():
                batch_x, batch_y = batch_x.cuda(), batch_y.cuda()
            tlabels, tpredi, tloss = train(model, batch_x, batch_y, optimizer, criterion)
        # 每个 epoch 结束，在测试集上评估一次
        acc_score, loss_score, feature_list, C = test(model, test_loader, criterion)
        print("Epoch %d Val_accuracy %.3f Val_loss %.3f" % (epoch, acc_score, loss_score))
```

**`unsqueeze(batch_x, dim=1)` 这行是干什么的？**
原始 batch 形状是 `(100, 10000, 12)`——没有"通道"这一维。
卷积层 `Conv2d(1, 5, ...)` 要求输入必须是 `(batch, channel, H, W)`，
所以在第 1 维插入一个"通道数=1"，变成 `(100, 1, 10000, 12)`。
**这就是"把时空矩阵当成灰度图"的具体实现。**

> **顺便纠正一个说法**：论文 4.2 节写"learning rate is set to 0.01"，
> 但代码第 143 行写死的是 `lr=1e-4`。
> 第 209 行虽然有个 `--lr default=0.01` 的参数，但**从头到尾没被用过**，是个死参数。
> **复现时以代码为准（1e-4）**，这是你向导师汇报时值得提的一个发现。

### 4. `feature_extraction.py`（56 行）—— SVM 的 16 维特征

**函数签名**：输入一条一维时序信号（长度 10000 或 9999），输出 16 个数字。

它算了 17 个统计量，**但只返回了 16 个**（下面标 ⚠️ 的就是被丢掉的那个）：

| # | 变量名 | 中文 | 物理含义 |
|---|--------|------|---------|
| 1 | `dif_max` | 最大值 | 信号最强到什么程度 |
| 2 | `dif_min` | 最小值 | 信号最弱到什么程度 |
| 3 | `dif_pk` | 峰峰值 | max − min，动态范围 |
| 4 | `dif_mean` | 均值 | 直流分量 |
| 5 | `dif_energy` | 能量 | 频域幅值平方的均值 |
| 6 | `dif_var` | 方差 | 波动程度 |
| 7 | `dif_std` | 标准差 | 波动程度（和方差同源） |
| 8 | `dif_rms` | 均方根 | 有效值 |
| 9 | `dif_arv` | 整流平均值 | 取绝对值后的均值 |
| 10 | `dif_boxing` | 波形因子 | rms / 整流均值 |
| 11 | `dif_maichong` | 脉冲因子 | max / 整流均值 |
| 12 | `dif_fengzhi` | 峰值因子 | max / rms |
| 13 | `dif_yudu` | 裕度因子 | max / (√\|x\|均值的平方) |
| 14 | `dif_kurt` | 峰度因子 | 分布有多"尖"（pandas 算的） |
| 15 | `dif_qiaodu` | 峭度因子 | 四阶矩 / rms⁴（numpy 算的） |
| 16 | `dif_entropy` | 信息熵 | 频域能量分布的混乱程度 |
| ⚠️ | `freq_spectrum` | FFT 幅值谱 | **算了，但没放进返回列表** |

**发现的 3 个问题**：

1. **信息熵的位置对不上**。论文 4.1 节列的 16 个特征里，最后一个是"information entropy"。
   代码里 `dif_entropy` 确实算出来了，但**返回列表第 16 项是 `dif_qiaodu`，entropy 被漏掉了**。
   也就是说代码实际返回的是"峰度+峭度"，论文说的"信息熵"没进去。

2. **峰度和峭度高度重复**。`dif_kurt`（pandas 的 kurt，超额峰度）和 `dif_qiaodu`
   （四阶矩/rms⁴，皮尔逊峭度）**描述的是同一个东西**，只是定义差 3。
   两个都放进去等于浪费一维。

3. **`dif_boxing` 和 `dif_fengzhi` 在信号全零时会除零**。背景噪声样本如果某个通道
   恒为常数，`abs(data).mean()` 就是 0，直接 `ZeroDivisionError`。
   我实测你的背景样本值域是 7828~8655，不是常数，所以**暂时不会触发**——
   但这是"跑得通但很脆"的代码，值得知道。

### 5. `get_das_data.py`（42 行）—— SVM 的数据组装

**逻辑很简单**，但有个著名的 bug：

```python
def get_diff_data(data):
    data_diff = np.empty([m-1, n]).astype(int)   # ← 注意这一行
    for i in range(m-1):
        data_diff[i, :] = data[i+1, :] - data[i, :]
    return data_diff
```

`np.empty([m-1, n])` 默认是 **float64**，`.astype(int)` 后变成 **int64**。
看起来没问题。**但原始数据是 `uint16`**：

- 如果 `data` 没先转 int，`data[i+1] - data[i]` 会按 uint16 运算
- `7800 - 8100 = -300` → 在 uint16 里**回绕成 65236**！

官方仓库 issue #2 就是这个问题：有人指出应该改成 float 再差分，
改完之后 SVM 准确率从原来的数字**涨到了 0.878**。

**好消息**：再看 `get_das_data()` 的实现：

```python
rawdata = scio.loadmat(path)['data']    # uint16
diffdata = get_diff_data(rawdata)       # ← 直接传进去了！
```

**`rawdata` 没有被 `.astype(int)`！** 所以理论上会触发回绕 bug。
……但实际跑出来准确率有 82%，说明 numpy 在 `data_diff[i,:] = data[i+1,:] - data[i,:]`
这个赋值时做了类型提升（右边的减法结果被提升成 int64 再赋给 int64 的左边）。

**这个坑你要自己在代码里验一次**，这是极好的科研训练：写 3 行代码，
打印 `get_diff_data` 前后的数值范围，看看有没有出现 6 万多的诡异数字。
**我建议你在自己的版本里显式加 `.astype(np.int32)`，消除这个不确定性。**

### 6. `das_data_svm.py`（97 行）—— SVM 训练主程序

**流程**：读数据 → MinMaxScaler → SVC(rbf) → 训练 → 预测 → 混淆矩阵 → 算指标。

**SVM 超参**（第 42~45 行，和论文一致）：

```python
svm.SVC(C=1.0, kernel='rbf', degree=3, gamma='auto',
        coef0=0.0, decision_function_shape='ovo', tol=0.001, max_iter=-1)
```

- `kernel='rbf'` 径向基核，处理非线性
- `C=1.0` 惩罚系数（越大越不容忍错分，容易过拟合）
- `gamma='auto'` = 1/特征数 = 1/384
- **`decision_function_shape='ovo'`**：one-vs-one，6 类要训练 C(6,2)=15 个二分类器。
  这是 **scikit-learn 的默认值**，写不写都一样

**⚠️ 这里有个真正的数据泄漏 bug（第 36~37 行）**：

```python
trainingData = minMaxScaler.fit_transform(X_train)   # fit + transform
testData = minMaxScaler.fit_transform(X_test)        # ← 又 fit 了一次！
```

`fit_transform` 会**重新计算**测试集自己的最小最大值，
而不是用训练集的 min/max 去变换测试集。

**为什么这是问题？** 因为测试集的信息泄漏进了预处理流程。
正确写法应该是：

```python
minMaxScaler.fit(X_train)                      # 只在训练集上 fit
trainingData = minMaxScaler.transform(X_train)  # 用同一把尺子
testData = minMaxScaler.transform(X_test)       # 变换测试集
```

**不过要客观说**：对 MinMaxScaler 而言，这个泄漏的影响通常**不大**
（只是缩放比例不同，不改变样本间的相对关系）。**但你必须在报告里指出这一点**——
"我发现官方代码存在数据泄漏，但我验证了它对 MinMaxScaler 影响有限"，
这句话的科研价值远大于"我跑出 82%"。

**⚠️ 第二个问题：指标计算跳过了第 0 类（第 91 行）**：

```python
for i in range(1, 6):        # ← 从 1 开始，class 0 (background) 被跳过了
    Precision = C[i-1][i-1] / column_sum[i-1]
```

论文 Table 4 是**算了 background 类的**（第 1 行：Precision 0.985, NAR 0.042, F1 0.971）。
所以你要把 `range(1, 6)` 改成 `range(6)` 才能对上论文。

**⚠️ 第三个问题：NAR 的定义和论文不一致**

| 来源 | NAR 定义 |
|------|---------|
| 论文公式 (2) | `NAR = FN / (TP + FN)` —— 就是**漏检率** |
| README (2024-06 更新) | `NAR = Σd₀ⱼ / ΣΣdᵢⱼ` —— **虚警率**（把背景误报成事件的占比） |
| 代码第 82 行 | 实现的是 README 那版（虚警率） |

**论文和 README 自己就打架了。** 复现时我建议你**两个都算、两个都报**，
并在报告里说明"论文公式(2) 与仓库 README 更新后的定义不一致，本文同时给出两者"。
**这是一个能体现你严谨性的点，导师一定会注意到。**

## 四、最重要的那个坑：30 小时 vs 7 分钟

`mydataset.py` 第 9-11 行：

```python
for i in range(data.shape[0]):        # 10000 次
    for j in range(data.shape[1]):    # × 12 次
        data[i][j] = round(...)        # = 12 万次 Python 层循环
```

**我在你的机器上实测了**（RTX 4050 / Python 3.13）：

| 版本 | 单个样本耗时 | 50 epochs 总计 |
|------|------------|---------------|
| 官方双层 for 循环 | **0.1436 秒** | **约 30.8 小时** |
| NumPy 向量化 | **0.0006 秒** | **约 7 分钟** |
| | **快 240 倍** | |

**而且两者结果完全一致**（我用 `np.array_equal` 逐个比对过）。

**这就是"Python 循环 vs 向量化"的经典教训**，也是你学深度学习必须建立的本能：
**见到 `for i in range(...)` 套在数组运算外面，就要条件反射地想"能不能向量化"。**

改法（一行替换）：

```python
# 官方写法（慢 240 倍）
def normalize(data):
    rawdata_max = max(map(max, data))
    rawdata_min = min(map(min, data))
    for i in range(data.shape[0]):
        for j in range(data.shape[1]):
            data[i][j] = round(((255 - 0) * (data[i][j] - rawdata_min)
                                / (rawdata_max - rawdata_min)) + 0)
    return data

# 向量化写法（等价，快 240 倍）
def normalize(data):
    rawdata_max = data.max()
    rawdata_min = data.min()
    return np.round(255.0 * (data - rawdata_min) / (rawdata_max - rawdata_min))
```

> **⚠️ 别急着改！** 先按官方原样跑一个 epoch **亲眼看到它有多慢**，
> 再改成向量化版本。**这个"从慢到快"的体验，比直接抄答案值钱得多**，
> 而且是你报告里一个很好的工程优化案例。

## 六、你的代码要怎么组织（重要）

**不要直接改官方源码！** 正确做法是让"官方原始版"和"你的改进版"并存：

```
das_rep\
├── Phi-OTDR_dataset_and_codes-main\   ← 官方原始版，一个字都别改
├── stage2\
│   ├── origin\          ← 第 1 步：只有路径改动的版本
│   └── fixed\           ← 第 2/3 步：你修过 bug 的版本
└── docs\
    └── bug_记录.md      ← 记录你发现的每个问题和修复效果
```

**为什么？** 因为导师问你"你和官方代码有哪些差异"时，
你可以直接 `diff` 给他看。**这是复现工作的核心证据**，
也是这篇文章里我最想让你养成的一个习惯。

**建议现在就建一个 `docs\bug_记录.md`**，格式：

```markdown
## Bug 1：mydataset.py 归一化用双层 for 循环
- 位置：mydataset.py 第 9-11 行
- 现象：单样本耗时 0.1436 秒，50 epochs 需 30.8 小时
- 原因：12 万次 Python 层循环
- 修复：改为 NumPy 向量化
- 效果：0.0006 秒/样本，快 240 倍，结果一致（np.array_equal 验证）
- 影响：无精度影响，纯性能
```

## 八、这一阶段你要真正学会的 5 件事

1. **PyTorch 数据加载三件套**：`Dataset` 的 `__init__` / `__len__` / `__getitem__`，
   以及 `DataLoader` 的 batch 机制——**以后所有项目都是这个套路**
2. **`unsqueeze(dim=1)` 的意义**：从 `(N, 10000, 12)` 到 `(N, 1, 10000, 12)`，
   为什么要插"通道"这一维
3. **向量化的本能**：见到数组运算套 `for` 循环，先想能不能用 NumPy
4. **复现 ≠ 抄代码**：要能指出原代码的问题，并量化影响
5. **保留证据链**：原始版/修改版并存 + bug 记录文档，
   这是你向导师证明"我真的读懂了这个工作"的方式

## 附：源码里几个值得琢磨的小细节

- `das_data_cnn.py` 第 145 行 `batches_per_epoch = int(len(train_dataset)/args.batch_size)`
  得到的是 **123**（batch 数），但变量名叫 "batches" 却用 `len(dataset)` 算——
  写法容易误导。实际 `len(DataLoader)` 才等于 124（12335/100 向上取整）
- 第 137 行测试集也用了 `shuffle=True`。评估时其实不需要打乱，
  但对最终指标无影响（因为是把所有预测收集起来统一算混淆矩阵）
- 两个脚本开头都用 `Logger` 类把 stdout 同时写到终端和日志文件——
  这是**很好的习惯**，建议你以后也这么做，方便回溯每次实验
- `feature_visualization.py` 里 `LinearDiscriminantAnalysis(n_components=3)`：
  LDA 是有监督降维（用到了标签），和 PCA（无监督）不同。
  LDA 最多降到 `类别数-1 = 5` 维，取 3 维是合理的
