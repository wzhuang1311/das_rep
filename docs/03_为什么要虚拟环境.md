# 为什么要建虚拟环境（venv）？

> 这是新手最容易"照做但不知道为什么"的一步。搞懂了，以后你换项目、换电脑、给导师交代码都不会踩坑。

---

## 一句话版本

**虚拟环境 = 给这个项目单独开一个装第三方库的抽屉。**
抽屉里的包只给这个项目用，动它不会影响别的东西；不想要了整个抽屉扔掉，电脑恢复原样。

---

## 先看没有 venv 会怎样：你机器上的真实数字

你的全局 Python（`C:\Users\34667\...\Python313`）现在是这样：

| 项目 | 实际值 |
|------|--------|
| `site-packages` 总大小 | **1.34 GB** |
| 里面顶层包（文件夹）数量 | **170 个** |
| 其中 `torch`（CPU 版） | 492 MB |
| 其实你只装了 8 个库 | torch / torchvision / torchaudio / sklearn / scipy / numpy / pandas / matplotlib / scikit-image |

**关键问题**：我们接下来要装 CUDA 版 torch，它会额外带上显卡驱动接口、cuDNN、cuBLAS 等一堆 NVIDIA 库，
**体积从 492 MB 涨到约 3 GB**。

现在有两条路：

| | 直接装进全局 | 装进 `das_rep\.venv` |
|---|---|---|
| 全局环境体积 | 1.34 GB → **约 4 GB** | 1.34 GB **不变** |
| 以后别的项目要 torch 2.9 | 得先卸载 2.12，再装 2.9，来回折腾 | 各装各的，互不干扰 |
| 装崩了怎么办 | **全局 Python 可能直接不能用**，修起来很痛 | 删掉 `.venv` 文件夹，30 秒重来 |
| 把项目发给导师/同学 | 对方不知道你装了啥版本，跑不起来 | 一条 `pip freeze > requirements.txt` 就能复现 |
| 想回到现在的状态 | 得手动卸载、清理残留，经常清不干净 | `Remove-Item .venv -Recurse` 一条命令 |

第四行是重点：**深度学习的库版本冲突极其常见**。比如有些论文代码要求 `numpy<2`，
有些要求 `numpy>=2`，装在同一个环境里**必然打架**。venv 就是官方给出的标准解法。

## 用生活类比理解

想象你在做菜：

- **全局环境** = 厨房只有一个灶台、一套调料。
  今天做川菜，明天做甜品，你得把花椒全收起来换成香草——**换一次要半小时，还容易漏**。
- **虚拟环境** = 每个项目一个独立的料理台，调料各备一份。
  川菜台永远保持川菜配置，甜点台永远保持甜点配置，**互不影响**。

代价只是"多占一点地方"（磁盘），换来的是"永远不用收拾灶台"。

## 技术上它到底做了什么？

其实非常简单，就三件事：

1. **建了一个文件夹** `.venv`，里面有自己的一份 `python.exe` 和 `Lib\site-packages`
2. **激活时改了一个环境变量 `PATH`**，让系统优先找到 `.venv\Scripts\python.exe` 而不是全局那个
3. 于是你敲的 `python`、`pip` 全都作用在这个文件夹里

**所以"激活"这个动作是可以随时开关的**，它不是安装，只是一个"切换当前用哪个 Python"的开关。

验证方法（强烈建议你记住这两条）：

```powershell
# 1. 我现在用的是哪个 Python？
python -c "import sys; print(sys.executable)"

# 2. 我现在装在哪个环境？（能看出是 .venv 还是全局）
python -m pip -V
```

激活后 `sys.executable` 会显示 `...\das_rep\.venv\Scripts\python.exe`；
**没激活就会显示全局路径**——这就是判断有没有激活成功的唯一可靠标准。

## 那为什么不用 conda？

你 `.vscode\settings.json` 里写着 conda，所以特意说明一下：

| | venv | conda |
|---|---|---|
| 从哪来 | **Python 自带**，装了 Python 就有 | 要额外下载安装 Anaconda/Miniconda（约 500 MB） |
| 装包速度 | 快 | 慢（要解依赖） |
| 科学计算包 | 从 PyPI 装，官方源 | conda 自己的源，有时版本旧 |
| 能否管非 Python 依赖 | 不能 | 能（如 CUDA Toolkit 本体、R 语言） |
| 新手友好度 | 命令少，概念简单 | 概念多（base 环境、channel、solve 冲突） |
| PyTorch 官方推荐 | ✅ **官网给的就是 venv + pip 命令** | 也支持 |

**结论**：你的需求就是"装几个 Python 库跑深度学习"，venv 完胜。
conda 的优势（管理 CUDA Toolkit 本体）我们用不上——PyTorch 的 wheel 里已经把 CUDA 运行库打包好了，
**根本不需要单独装 CUDA Toolkit**。

> 你 VSCode 里那个 `python-envs.defaultEnvManager: conda` 设置，直接无视就行
> （机器上根本没装 conda，它也不会去找）。

## 什么时候不需要 venv？

诚实地说——**像你这次只做一个项目、机器上没别的 Python 项目，不建 venv 也能跑通。**

但我还是建议建，因为：

1. **可逆**：装 CUDA 版 torch 有 3 GB，万一把全局搞出问题，你会卡好几天
2. **你要向导师交东西**：有 venv 就能导出 `requirements.txt`，这是"我确实复现出来了"的硬证据
3. **你迟早会有第二个项目**：一篇论文做完还有下一篇，到时候你会庆幸当初分了抽屉
4. **成本极低**：多敲 2 条命令，多占 3 GB 磁盘（你 D 盘还剩 139.7 GB）

## 附：venv 的 5 条常用命令（存下来）

```powershell
# 1. 创建（只需一次）
py -3.13 -m venv .venv

# 2. 激活（每开一个新终端都要做一次）
.\.venv\Scripts\Activate.ps1

# 3. 退出（回到全局环境）
deactivate

# 4. 导出依赖清单（交给导师/同学用）
python -m pip freeze > requirements.txt

# 5. 按清单复现环境（别人拿到你的项目后）
python -m pip install -r requirements.txt
```

**第 5 条就是 venv 的终极价值**：导师拿到你的 `das_rep` 文件夹，
照着 `requirements.txt` 一条命令就能装出和你一模一样的环境，
然后跑出和你一模一样的结果。**没有 venv，这件事做不到。**

## 附：彻底卸载重来（搞坏了就用这个）

```powershell
# 1. 先退出
deactivate

# 2. 回到 das_rep 目录，删掉整个 .venv 文件夹
cd "D:\汕头大学\科研\深度学习\text.demo\das_rep"
Remove-Item .venv -Recurse -Force

# 3. 重新走"创建 → 激活 → 装包"三步
```

**全局环境一点没被碰过**——这就是"可逆"的含义，也是我坚持让你用 venv 的真正原因。
